# Если что-то не работает

Сначала откройте логи: консоль при локальном запуске, вкладку **Logs** на Render или `journalctl -u funpay-bot -f` на VPS. Найдите в таблице ниже сообщение, похожее на ваше.

| Что видно | Причина | Что делать |
|---|---|---|
| `KeyError: 'FUNPAY_GOLDEN_KEY'` (или другая переменная) | Переменная не задана | Заполните `.env` или переменные окружения на хостинге ([SETUP.md](SETUP.md)) |
| `UnauthorizedError` / 403 при старте | `golden_key` неверный или устарел | Скопируйте `golden_key` заново из браузера |
| `Telegram (chat …): 401 Unauthorized` | Неверный токен бота | Проверьте, что токен вставлен целиком, вместе с частью до `:` |
| `Telegram (chat …): 400 Bad Request: chat not found` | Неверный chat id | Проверьте id у [@userinfobot](https://t.me/userinfobot) |
| `Telegram (chat …): 403 Forbidden: bot can't initiate conversation` | Получатель не нажал Start | Откройте бота и нажмите **Start** |
| `Произошла ошибка при получении событий` на каждом запросе | FunPay отклоняет запросы к `runner/` | См. ниже «FunPay поменял сайт» |
| `Не удалось получить истории чатов [...]`, заказы приходят, а сообщения нет | FunPay поменял HTML чата | См. ниже «FunPay поменял сайт» |
| Уведомления приходят дважды | Бот запущен в двух местах | Оставьте только одну копию |
| На Render бот засыпает | Нет пинга | Проверьте монитор в UptimeRobot ([DEPLOY.md](DEPLOY.md)) |

Ошибка `Произошла ошибка при получении событий`, которая появляется **редко**, — это нормально: FunPay иногда отвечает с перебоями. Тревожиться стоит, только если она идёт на каждом запросе.

## FunPay поменял сайт

Бот работает через неофициальную библиотеку, которая разбирает HTML и внутренние запросы сайта. Когда FunPay их меняет, бот ломается. Так уже было дважды:

- **Ошибка 400 у `runner/`** с ответом `Необходимая cookie отсутствует или устарела`. FunPay начал требовать cookie `golden_seal`. Исправлено функцией `_patched_method` в `bot.py`, которая отправляет запросы через `requests.Session` со всеми cookie.
- **`AttributeError: 'NoneType' object has no attribute 'text'`** при разборе сообщений. Класс `message-text` переименовали в `chat-msg-text`. Исправлено функцией `_patched_parse_messages`.

Как искать новую поломку:

1. Запустите бота локально и посмотрите полный traceback.
2. Если ошибка в ответе сервера, выведите `e.response.text`: FunPay обычно пишет причину.
3. Если ошибка при разборе HTML, выведите `html` сообщения и сравните классы с тем, что ищет парсер в `FunPayAPI/account.py`.
4. Добавьте заплатку в `bot.py` по образцу существующих и пришлите pull request 🙂
